# Globals — every `window.<name> =` assignment
Purpose: the modules talk through `window`; this is name → `file:line,line` for every assignment. Read this when you need the definition (or every wrapper) of a cross-module function or flag. Skip it when the name is local to one file.

> Generated by agents/tools/build-index.mjs from working tree (uncommitted changes on top of `ebc2926`). Do not edit; rebuild with `npm run agents:index`.

196 names. More than one site = a later module wraps or re-exports it. "function <file>:<line>" = the name is a top-level `function` of a classic script; "re-exported" = a plain `window.f = f;`; "wrapped by" = a site that REASSIGNS it to something else (a wrapper: read it before you change the arguments of the function or rely on its return value). A wrapper installed through a computed key (`window[name] = …` inside a helper such as `wrapGlobal('toggleLocation', saveFilters)`, or over a literal list) is listed under each name it is given.
Sites are in SCRIPT LOAD order (an inline script of a shell, then psycle-finder.html's `<script src>` order, then ios-app/www/native-bridge.js, which only the iOS build loads, last). Load order is not install order: some wrappers install when their file runs, others later (from a `setTimeout`, a poll that waits for app.js, `DOMContentLoaded`) — read the install site before you say which wrapper is outermost. A bare call such as `submitBooking(…)` reaches whichever wrapper was installed LAST.
Also global, and NOT repeated here: every top-level `function` of the files that are not wrapped in an IIFE — js/app.js, js/calendar.js, js/performance.js, js/theme.js — see `symbols/`. `window.on…` handlers and `window.location` are left out.
