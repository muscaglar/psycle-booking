# Class-type colours — the palette, the three intensities, `PsycleClassColours`, the member's control
Read this when you touch a swatch, an intensity, `data-ct`, a pictogram or Membership → Class colours. Skip it otherwise: it is one dense paragraph.

**Class-type colours (Crisp Colour)**: colour means CLASS TYPE and nothing else. The eight categories of `CATEGORY_MAP` (js/app.js; keys lower-cased: ride, strength, yoga, hiit, pilates, lagree, barre, other) each wear one swatch of ONE curated palette in js/theme.js (`pure:class-colours`: cobalt, sky, teal, jade, moss, sun, ember, rose, orchid, violet, slate — every swatch ships precomputed `tintSoft / tintBold / base / deep / ring / drop` for light AND dark bases; no colour maths at runtime, no `color-mix()` / `oklch()`), at one of three intensities — `off` (cards stay the neutral surface; colour only in the pictogram tile and small marks), `soft` (**default**: a card tint half-way between the boards' tint and the surface, and a calm tile) and `bold` (the boards as drawn). `window.PsycleClassColours = { PALETTE, DEFAULTS, KEYS, INTENSITIES, get(), set(partial), reset(opts), apply(), clean(value), resolve(key) }`: `apply()` writes `--ct-<key>-*` + `--ct-on-base` inline on `<html>` and `html[data-ct-intensity]`, runs from `_applyTheme` (so when the deferred js/theme.js first runs — NOT at first paint: the `themeBoot` script sets the theme only — and on every light ↔ dark switch; nothing in the static markup is class-coloured any more: the header's `.brand-mark` is the app icon's two engraved halves in the theme's two inks, `--text-heading` over `--text-ghost`, right from the first paint), skips the DOM when nothing changed, and emits `classcolours:changed`; `resolve(key)` reads the literal colours back for a canvas. css/theme.css ENDS with the same values for the default map as plain CSS (tests hold the two together). Terminal and Handheld (`mono`) get no inline values unless the member chose `bold`: the stylesheet maps every type onto the theme's accent ladder. Components get their type as `data-ct` (`classTypeKey(typeName)`) and read ONLY `--ct-tint / -wash / -base / -deep / -ring / -drop`, `--ct-card`, `--ct-tile`, `--ct-tile-ink`, `--ct-ink`, `--ct-ink-2` from css/crisp.css's one mapping block; `CATEGORY_MAP[i].color` survives only as a getter (the base colour in effect) for older call sites. Pictograms: `classPictogram(key, size)` (`pure:class-type` — eight stroke marks, `currentColor`, aria-hidden, never an emoji). tests/suites/9a-foundation.js checks every swatch × role × base × theme against the ink it carries. The member's control is Membership → Appearance → **Class colours** (js/tabs.js `renderClassColours`, `pure:class-colour-control`): an Off · Soft · Bold radio group, one disclosure row per class type (pictogram tile, name, the chosen swatch's name + dot) that opens that type's swatches as a radio group (arrows move AND choose; the chosen one carries a tick and a ring; ONE row open at a time, so only eleven swatches are ever in the DOM), a live preview built from the real class component, and Reset colours. It keeps no copy of the choices: everything goes through `PsycleClassColours.set()` / `reset()`, it repaints on `classcolours:changed` / `theme:changed`, and on a mono theme below Bold it says "Shown at Bold only in this theme." The heatmap is deliberately NEUTRAL — colour keeps one meaning.
