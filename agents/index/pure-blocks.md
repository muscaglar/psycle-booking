# Pure blocks — the marked regions the tests evaluate alone
Purpose: every `// ── pure:<name>:start` … `:end` region (and the legacy `waitlist:pure` pair): where it is, what it declares, which suite loads it. Read this when you change a helper a test evaluates, or need a home for a new testable helper. Skip it for DOM or CSS work.

> Generated by agents/tools/build-index.mjs from working tree (uncommitted changes on top of `427bc69`). Do not edit; rebuild with `npm run agents:index`.

68 blocks. A name may repeat in one file (regions are concatenated in file order by `t.loadPure`) and regions nest. "loaded by" = the suites that call `loadPure(file, name)` or slice the markers themselves (`tests/unit.js` evaluates `waitlist:pure`).
Most regions are DOM-free helpers. 5 are UI or IO code that a suite evaluates against fakes (marked NEEDS FAKES, with what the code reaches for: `document.`, `fetch(`, `caches.`, storage, `navigator.`): `pure:tier-filter`, `pure:ics-share`, `pure:build-id`, `pure:calendar-sync`, `pure:settings-export`. Read the loading suite before you load one of those bare — the fakes go in as the third argument of `t.loadPure` — and do not treat one as a home for a pure helper. A NEW pure block stays free of DOM and app globals.
