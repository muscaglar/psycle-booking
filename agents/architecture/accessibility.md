# Accessibility plumbing — announcements, dialogs and the overlay stack, seat buttons, clickable non-buttons
Read this when you add an overlay, a toast, a control that is not a `<button>`, or change focus handling. Skip it otherwise.

**Accessibility plumbing**:
- *Announcements*: `announce(text, assertive)` writes to two fixed live regions that are in the page from the start (`#srStatus` polite, `#srAlert` assertive; `#toast` itself stays un-roled so nothing is spoken twice). `toast()` calls it for every toast; the session banner and the Booked! sheet announce too. Messages within one tick are joined in order; toast duration scales with length (3.5–10s, `_toastDuration`). Because a screen reader treats everything outside an open `aria-modal` dialog as inert, the same line is ALSO written to a live region created inside the top-most open dialog (`_dialogLiveRegion`, `_topDialogIndex`; a dialog that is fading out — `_psycleClosing` — is skipped).
- *Dialogs*: every sheet and modal is `role="dialog" aria-modal="true"` with a label and a focusable panel. ONE document `keydown` handler and ONE focus stack in app.js serve the eight plain overlays listed in `_OVERLAYS` (`_overlayStack`, kept in step by a MutationObserver through `_syncOverlayStack`): focus moves in on open (the bike picker starts ON the relevant seat), Tab is contained, a single Escape closes only the top layer through that overlay's real closer, and focus returns to the opener (or to its visible stand-in, `_visibleOpener` — see My Bookings card + More menu). `confirmModal`, the first-run welcome (full screen, swipeable; own keys and focus containment) and the usual-week sheet keep their own keys (`_ownKeysOverlayUp`) and sit above the stack. A new overlay must be added to `_OVERLAYS` (or manage its own keys and be listed in `_ownKeysOverlayUp` / `_dialogOpen`).
- *Seat buttons*: picker seats are SVG `<g>` nodes made operable by `_syncBikeSlotsA11y` after every change — `role="button"`, a name read from the seat's own label ("Bike 12, available, your usual"), `aria-pressed` for a selectable seat, `aria-disabled` + `tabindex="-1"` for a taken one; a seat already held is an action, not a toggle (`_bikeSlotA11y`, `pure:a11y`).
- *Clickable non-buttons* (`[role="button"]:not(button)` — instructor names, class titles, period bars, the next-class pill, seats) activate on Enter at keydown and on Space at keyup, from the same handler. Selected state is exposed, not just styled: `aria-pressed` on filter chips, date buttons, calendar days, theme chips, the favourite stars and the notify bell; `role="switch"` + `aria-checked` on the reminder rows; `aria-current="page"` on the tab bar.

**Adding an overlay**: the checklist is agents/playbooks.md P5; the pitfalls are agents/learnings.md E3–E7, D3 and H6; frames and the z-index ladder are in [design-system.md](design-system.md) → "Overlays".
- `_focusIntoOverlay` runs from the MutationObserver microtask and focuses the `[role="dialog"]` panel ON PURPOSE, so the name is read and no iOS keyboard pops. A field that wants the caret is focused after that (a `requestAnimationFrame`), and on iOS the keyboard rises only from a user gesture.
- The focus stack orders overlays by when they OPENED, not by z-index. An overlay must sit above whatever can open it, and anything that opens a sheet unasked (the bridge's `_routeNotificationTap` calls `openClassDetail` with no overlay check) can put focus and Escape on a layer hidden underneath.
