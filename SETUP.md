# Psync — development setup

## Prerequisites

- macOS
- Python 3 (comes with Xcode Command Line Tools)
- Node.js (v20+)
- Xcode (for iOS builds)
- CocoaPods (`sudo gem install cocoapods` if not installed)

## Web App (PWA)

```bash
# Clone and serve
git clone <your-repo-url> psycle-booking
cd psycle-booking
python3 -m http.server 8080
```

Open http://localhost:8080/psycle-finder.html

That's it — no build step, no npm install for the web app.

To run the checks (syntax, unit tests, iOS bundle drift): `npm run ci` from the repo root. See README.md and
tests/README.md.

> The Psycle API the app talks to is a real booking system. Never drive booking, cancel or waitlist flows against
> it from tests or tooling — stub it first (tests/README.md has the recipe).

## iOS App (Capacitor)

The Xcode project under `ios-app/ios/` **is committed** — the app target, the widget extension, the Live Activity,
the App Intents, entitlements and the scripted target wiring all live there. Do not delete it and do not re-create
it with `npx cap add ios`: that would throw away the native targets and their wiring (see
ios-app/NATIVE_FEATURES.md).

What is NOT committed, and is regenerated by the commands below: `node_modules/`, CocoaPods' `Pods/`, and the
copies Capacitor places inside the project on every sync (`ios/App/App/public/`, `ios/App/App/capacitor.config.json`,
`config.xml`).

### First time setup (fresh clone)

```bash
cd ios-app
npm ci          # Capacitor + plugins; postinstall patches the calendar plugin (patch-plugins.js)
npm run sync    # patch plugins → build www/ → npx cap sync ios (copies web assets, runs pod install)
npm run open    # opens the workspace in Xcode
```

### If the iOS project is in a bad state

Restore the committed project, then reinstall the pods:

```bash
git checkout -- ios-app/ios
cd ios-app/ios/App && pod install
```

If web assets or the Capacitor config inside the project are missing as well, follow with
`cd ios-app && npm run sync`.

### Node version issues

If `npx` or `node` isn't found, ensure your Node version is set:
```bash
# If using asdf
asdf install nodejs 20.19.5
asdf local nodejs 20.19.5

# If using nvm
nvm install 20
nvm use 20
```

### Xcode setup (first time only)

1. After `npm run open`, Xcode opens the **workspace**
2. **IMPORTANT**: Always open `App.xcworkspace`, never the `.xcodeproj`
3. Select your development team: **Signing & Capabilities** → **Team** (for the app target AND the widget extension)
4. Set the bundle identifier: `com.psyclefinder.app` (or your own — if you change it, the widget extension's
   bundle id and the App Group id `group.com.psyclefinder.app` have to change with it; see
   ios-app/NATIVE_FEATURES.md)
5. Select a connected iPhone or simulator
6. **Product → Run** (or `Cmd+R`)

The first signed build on a device registers the App Group and the widget bundle id with your developer account;
until then the widget cannot read the app's data.

### Rebuilding after code changes

```bash
# After editing any js/ or css/ files:
cd ios-app
npm run sync

# Then in Xcode: Cmd+R to rebuild
```

Or use the shortcut:
```bash
cd ios-app && npm run build:open
# (runs sync, then opens Xcode)
```

`npm run build` on its own only regenerates `ios-app/www/` and the service-worker cache stamp (no `cap sync`, no
Xcode). That is the command to run — and commit the result of — after any change to the web source, so that
`npm run drift` stays green. `npm run sync:check` is the same dry-run check from inside `ios-app/`.

### ios-app npm scripts

| Script | What it does |
|--------|--------------|
| `npm run build` | Regenerate `www/` + stamp the SW cache version (`node build.js`). Idempotent |
| `npm run sync` | `patch-plugins.js` → `build.js` → `npx cap sync ios` |
| `npm run open` | `npx cap open ios` |
| `npm run build:open` | `sync`, then open Xcode |
| `npm run sync:check` | Dry run: exits non-zero if `www/` or the SW cache stamp is out of date |
| `npm run patch` / `patch:check` | Apply / verify the native plugin patch (also runs on `postinstall`) |
| `npm run update-web` | Alias of `build` |

### Common issues

| Problem | Fix |
|---------|-----|
| `Unable to open base configuration reference file .xcconfig` | Pods are missing: `cd ios-app/ios/App && pod install` (or `cd ios-app && npm run sync`) |
| `capacitor.config.json: No such file or directory` | The synced copy inside the project is missing: `cd ios-app && npm run sync` |
| `public: No such file or directory` | Same — `npm run sync` copies `www/` into `ios/App/App/public/` |
| Project file damaged / targets missing | `git checkout -- ios-app/ios`, then `cd ios-app/ios/App && pod install` |
| `pod: command not found` | `sudo gem install cocoapods` |
| `No version is set for command node` | Set node version via asdf/nvm (see above) |
| `patch-plugins` fails loudly after a dependency bump | The calendar plugin changed upstream; the patch is pinned to 6.7.2 on purpose — see ios-app/patch-plugins.js |

## Android App (Capacitor)

The same wrapper holds the Android project (`ios-app/android/`). It needs Android Studio, a JDK 17 and Node — or
nothing at all, if you take the debug APK that GitHub Actions builds. Everything is in
[ios-app/ANDROID.md](ios-app/ANDROID.md): `cd ios-app && npm ci && npm run sync:android && npm run open:android`.
`npm run sync` (above) stays iOS-only.

## App Icon & Assets in Xcode

### App Icon

The committed AppIcon set is already **Single Size**: `AppIcon.appiconset/Contents.json` has one universal
1024×1024 entry (`AppIcon-512@2x.png`) and Xcode generates every other size from it. To change the icon:

1. In Xcode, open the project navigator (left sidebar)
2. Navigate to **App → App → Assets.xcassets → AppIcon** — there is a single 1024pt slot
3. Drag `ios-app/appstore-assets/AppIcon-1024.png` (or your own 1024×1024 PNG) into it

There is nothing else to fill in or enable. The per-size files in `ios-app/appstore-assets/` only matter if you
switch the set back to **All Sizes** in the Attributes Inspector; in that case the slots map as follows:

| File | Xcode slot |
|------|-----------|
| `AppIcon-20.png` | Notification 20pt @1x |
| `AppIcon-40.png` | Notification 20pt @2x, Spotlight 40pt @1x |
| `AppIcon-58.png` | Settings 29pt @2x |
| `AppIcon-60.png` | Spotlight 20pt @3x |
| `AppIcon-76.png` | iPad App 76pt @1x |
| `AppIcon-80.png` | Spotlight 40pt @2x |
| `AppIcon-87.png` | Settings 29pt @3x |
| `AppIcon-120.png` | iPhone App 60pt @2x, Spotlight 40pt @3x |
| `AppIcon-152.png` | iPad App 76pt @2x |
| `AppIcon-167.png` | iPad Pro App 83.5pt @2x |
| `AppIcon-180.png` | iPhone App 60pt @3x |
| `AppIcon-1024.png` | App Store 1024pt @1x |

(The web app's own icons live in `icons/` at the repo root and are used by the PWA manifest and by the pages'
favicon / apple-touch-icon links; `ios-app/build.js` does not copy them into the iOS bundle.)

### Launch Screen

The committed launch screen is Capacitor's stock one: `LaunchScreen.storyboard` shows the `Splash` image
full-screen, and `Splash.imageset` holds the default opaque white 2732×2732 PNGs with no dark variant — so it is
white in Dark Mode too. To customise:
1. In Xcode: **App → App → Assets.xcassets → Splash**
2. Replace the splash image, or
3. Edit `ios/App/App/Base.lproj/LaunchScreen.storyboard` directly

### App Display Name

To change the name shown under the icon on the home screen:
1. In Xcode: select the **App** target → **General** tab
2. Change **Display Name** (the app ships as `Psync`, matching `appName` in `capacitor.config.json`)

### Status Bar Style

The `ios` block of `ios-app/capacitor.config.json`:
```json
{
  "ios": {
    "contentInset": "never",
    "allowsLinkPreview": false,
    "preferredContentMode": "mobile"
  }
}
```

`ios.backgroundColor` is deliberately **not** set. Capacitor then paints the WebView with
`UIColor.systemBackground`, which follows Dark Mode; any fixed colour flashes before first paint for whichever
half of the members it doesn't suit. (The launch screen itself is still Capacitor's stock white splash image —
see Launch Screen above.)

The native bridge (`www/native-bridge.js`) sets the status bar glyph style from the active theme's base: dark
glyphs on a light theme, light glyphs on a dark one.

### App Store Screenshots

Upload the framed screenshots from `ios-app/appstore-assets/`:
1. Log in to [App Store Connect](https://appstoreconnect.apple.com)
2. Go to your app → **App Information** → **Screenshots**
3. Upload the `01-` through `06-` framed PNGs (1290x2796, 6.7" iPhone)
4. Upload `AppIcon-1024.png` as the App Store icon

Full App Store copy (description, keywords, etc.) is in `ios-app/APP_STORE_LISTING.md`.

## Playwright (for automated screenshots / testing)

```bash
pip3 install playwright
python3 -m playwright install chromium
```

Then from the repo root:
```bash
python3 -m http.server 8080 &
python3 -c "
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    browser = p.chromium.launch(headless=False)
    page = browser.new_page()
    page.goto('http://localhost:8080/psycle-finder.html')
    input('Press Enter to close...')
    browser.close()
"
```

Before driving any flow that books, cancels or touches a waitlist, stub the API in the page — see
"Driving the app against a stubbed API" in tests/README.md.
