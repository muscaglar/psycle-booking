# Storage keys — who reads, writes and removes each `psycle_…` key
Purpose: every `psycle_…` string literal in the shipped code, by key: read / write / remove sites as `file:line,line`, plus membership of the four key lists. Read this when you add or change a stored key, or chase who clears one. Skip it otherwise. What each key HOLDS: agents/architecture/storage-keys.md.

> Generated by agents/tools/build-index.mjs from working tree (uncommitted changes on top of `9836e6a`). Do not edit; rebuild with `npm run agents:index`.

How a site is classed: the key (or a `const NAME = 'psycle_…'` that names it, same file) is the FIRST argument of a call — `getItem` → read, `setItem` / a `…set|save|store|write…` helper → write, `removeItem` / `…remove|clear|delete…` → remove. Everything else (a comparison, an entry of some other list, a key passed on as a later argument or through another variable) is `other` — open those lines before you conclude a key is never written. An entry of one of the four key lists below shows as a tag on the heading instead. A name ending `*` is a prefix the code appends to.
Not every literal is a storage key: one tagged "no storage call found" may be something else (`psycle_sec` is an IndexedDB name, `psycle_token` a URL parameter, `psycle_login` a window name). An `other` hit inside `_planSettingsImport` (js/settings.js) is that key's branch of the settings import — the shape check and the "only where the device has none" rule, and the branch to copy for a new exported key.
