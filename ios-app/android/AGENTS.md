# ios-app/android/ — read before editing here
The Android shell of the same Capacitor 6 app: a Gradle project, one activity, the manifest, resources — and the two features written natively here: the home-screen widget and the class countdown (one silent notification, Android's stand-in for the Live Activity). It wraps the SAME [../www/](../www/) and the same bridge as the iPhone app. The repo-wide rules are in the root [AGENTS.md](../../AGENTS.md) — this file adds only what is local; the folder above has its own [AGENTS.md](../AGENTS.md).

## Rules that bite here
The rule → why → its guard. Suites are in tests/suites/; G… are entries in agents/learnings.md.
1. **Nobody compiles this locally: CI is the compiler** (root rule 5). No JDK or Android SDK is assumed on a development machine → push to an `android/**` branch and read the `android-build` job (playbooks P14). Until it is green the change is "read, not built"; when it is green it is "compiled, not seen on a device" (G7, G9) → add a line to the checklist in [../ANDROID.md](../ANDROID.md).
2. **Small, conventional, read twice.** Well-formed XML; resource FILE names `[a-z0-9_]` only; every `@type/name` and style parent exists; only androidx classes the pinned versions carry (variables.gradle); only APIs that exist from minSdk 22 — anything newer goes in a qualified folder, as values-v23/ and values-v27/ do (a style in a qualified folder REPLACES the one in values/; `values-night/` outranks an API level). Guard: 19-android-project.js parses every XML under res/ and resolves every reference; its first section proves it can fail. It is not aapt2.
3. **GENERATED — never hand-edit**: capacitor.settings.gradle and app/capacitor.build.gradle (`cap sync android` rewrites them: commit them after a plugin change, as the Podfile is on iOS); the git-ignored app/src/main/assets/public/, assets/capacitor.config.json, assets/capacitor.plugins.json, res/xml/config.xml and capacitor-cordova-android-plugins/ (Gradle cannot run without them → `npm run sync:android` first); the res/mipmap-*dpi/ PNGs (`sh assets/render-icons.sh android`). Guard: 19-android-project.js fails if a generated path is tracked.
4. **Back**: `MainActivity` evaluates `(window._psycleAndroidBack ? window._psycleAndroidBack() : false)` and, on anything but `"true"`, calls `moveTaskToBack(true)`. Never `finish()`, never a default `onBackPressed()`, no timeout, no @capacitor/app plugin. WHAT closes is the web layer's business (js/app.js, `pure:android-back`). Because Back never finishes it, one activity lives for days: `uiMode` STAYS in the manifest's `configChanges` (a recreation reloads the web view under a request in flight), and `onConfigurationChanged` re-reads the navigation-bar colour and the web view's ground — dark navigation buttons from API 27 only, as values-v27/ has it. Guard: 19-android-project.js reads every .java file of the package.
5. **No new Capacitor plugin package and no new npm package**: a plugin package is an iOS pod, and ../package.json's dependencies and ../package-lock.json must not change again (Xcode Cloud runs `npm ci`, then `npm run sync`, which stays iOS-only). A LOCAL plugin — a Java class here, registered in `MainActivity` — is neither (rule 12). No new runtime Gradle dependency either, no Kotlin, Compose or Glance: app/build.gradle gained ONE line, `testImplementation "org.json:json:20240303"`. Guard: 19-android-project.js (the scripts, the lockfile, the exact dependencies block, ci_post_clone.sh knows nothing of Android).
6. **Backups off, cleartext off** (`allowBackup="false"` + res/xml/backup_rules.xml + res/xml/data_extraction_rules.xml, every domain excluded): what the app stores is a sign-in. ONE exported component, by necessity: the launcher — which ANY app can start with extras of its choosing: the bridge refuses what a forged notification tap could abuse (android.md → Notifications), and a widget tap's id is untrusted (rule 14). The widget's provider is `exported="false"`: the SYSTEM's widget service sends the widget broadcasts (a launcher never does) and may send to any receiver, and the app's own refresh and alarm are sent as the app — do not "fix" it to `true`; it takes NOTHING from an intent all the same. The countdown has the only other two (rule 18), unexported too: the one that plans, whose filter holds FOUR broadcasts only the system may send — `BOOT_COMPLETED`, `MY_PACKAGE_REPLACED`, `TIMEZONE_CHANGED`, `TIME_SET` — and the one the notification's delete intent reaches, with NO filter; the provider stays the FIRST `<receiver>` (19-android-project.js reads the first as the provider). No service of the app's own, no custom URL scheme or host, portrait only. A live-reload run needs cleartext lifted locally — never commit that, nor `server.url`, `server.allowNavigation` or `server.hostname` in ../capacitor.config.json. Guard: 19-android-project.js reads both rule files domain by domain and holds the exported components to the launcher alone.
7. **No secret, ever — the repository is public**: no keystore (`*.jks`, `*.keystore`, `*.p12`, `*.pfx` — a current keytool writes PKCS12), no password, no keystore.properties. app/build.gradle reads `PSYNC_KEYSTORE_FILE`, `PSYNC_KEYSTORE_PASSWORD`, `PSYNC_KEY_ALIAS`, `PSYNC_KEY_PASSWORD` from the environment or from keystore.properties (git-ignored); with any missing a release is UNSIGNED, never debug-signed. Guard: 19-android-project.js (tracked files, both .gitignore files, no literal password in a Gradle file).
8. **Names that other files hold** → change both sides: `AppTheme.NoActionBar` (`BridgeActivity` switches to it by name); `ic_stat_psync` and `#1B2130` (`ANDROID_NOTIF_ICON` / `ANDROID_NOTIF_TINT` in ../www/native-bridge.js, and `plugins.LocalNotifications` in ../capacitor.config.json); `psync_ground` by day and by night = the `bg` of Cloud and Graphite in js/theme.js `APP_THEMES`, and `android.backgroundColor` = Cloud's; `READ_CALENDAR` / `WRITE_CALENDAR` (the calendar plugin's manifest declares nothing). Guard: 19-android-project.js, "Android seams".
9. **The SDK levels belong to the Capacitor major** (variables.gradle: minSdk 22, targetSdk 34, compileSdk 35; AGP 8.2.1; Java 17). compileSdk 35 is deliberate (the calendar plugin pins androidx.core 1.15.0; gradle.properties silences AGP's warning). Do not raise targetSdk by hand — at 35 Android enforces edge-to-edge and ignores the bar colours in values/ — and do not accept Android Studio's offer to upgrade AGP or Gradle.
10. **The mark is drawn four times as vectors** — ic_launcher_foreground.xml (its note explains the geometry and why the grooves are real holes), ic_launcher_monochrome.xml, splash_mark.xml, ic_stat_psync.xml → change one, change all four. The launcher vectors use LITERAL colours on purpose; splash_mark.xml follows night. No guard: 12-brand-mark.js does not read them.
11. **Platform behaviour is not written here — the widget and the class countdown excepted** (rules 12–18). Channels, the status-bar colour, the calendar shapes, the copy and the countdown's off switch are `IS_ANDROID` branches of the bridge; the iPhone path must stay byte-identical → 18-android.js (`IPHONE_LAUNCH_DIGEST`). Bridge code still needs no phone: `harness(t).boot({ platform: 'android' })`.
12. **The three plugins are TWINS: keep their names and method shapes in step with ../ios/App/App/AppGroupPreferences.swift.** The bridge finds `AppGroupPreferences` (`set` / `get` / `remove`, each `{group, key…}`), `WidgetCenter` (`reloadAllTimelines`) and `PsycleDeepLink` (the event `'openURL'` `{ url }`, retained) BY NAME and has no Android branch for them: a renamed method is a widget that silently never updates. Register each in `MainActivity` BEFORE `super.onCreate`. `set()` must have stored the value when it returns (the bridge does not await it before the reload). `PsycleLiveActivity` gets NO twin, ever: the countdown is planned from `WidgetCenterPlugin.reloadAllTimelines` (rule 18). Guard: 19-android-project.js and 20-android-widget.js hold the Java, the Swift and the bridge to each other.
13. **A widget layout is inflated by the LAUNCHER, through RemoteViews** → FrameLayout, LinearLayout, RelativeLayout, GridLayout, TextView, ImageView (and the few others the suite lists) ONLY: no ConstraintLayout, `<View>`, `<Space>` or custom view, no `app:` attribute, no `?attr/` of the app's theme, no `android:onClick`. A colour is a WHITE shape in an ImageView + `setColorFilter` (RemoteViews cannot colour a shape); an API above 22 sits behind `Build.VERSION.SDK_INT` (`setColorInt` is 31); set every text, colour and visibility on EVERY build (a launcher re-applies onto views it already inflated); write ids `@+id/`; no sample text in a class layout; a one-line text style carries `android:ellipsize="end"` (`maxLines="1"` alone wraps at the last space and HIDES the rest — a seat number gone, unseen), and `singleLine` too where the text has no space to wrap at; the `initialLayout` (widget_next_class_loading.xml) claims nothing — "Nothing booked" is for a snapshot that was read. Build views in `PsyncWidgetViews` only — the provider and the debug preview must draw the same thing. Guard: 19-android-project.js; an `ActionException` on a launcher is beyond it.
14. **The tap is an EXPLICIT intent with an untrusted extra — never an intent filter with a scheme.** No `<data>`, no `psync://` in the manifest, no second filter on `MainActivity`; every `PendingIntent` is `FLAG_IMMUTABLE`, the tap's also `FLAG_UPDATE_CURRENT` (`PsyncTapIntent.immutableFlags`); the id is 1 to 12 digits or dropped (`PsyncSnapshot.tapId`), and the page judges it again. ONE builder, widget/PsyncTapIntent.java, serves the widget's card AND the countdown's notification — never copy it; their request codes differ (`FROM_WIDGET` 0, `FROM_COUNTDOWN` 1), so one being rebuilt never changes the id the other carries. The repaint alarm is `AlarmManager.setWindow(RTC, at, ten minutes, …)` — inexact, no permission — and NEVER the bare `set(…)`: the system picks that window (three quarters of the wait; at most an hour from Android 12, no cap before), so a started class could sit on the card for an hour (G16). WHEN it fires is `PsyncSnapshot.nextRepaintMillis` (the roll-over, or midnight if sooner: the day words are relative), never arithmetic in the provider, and it is armed in a `finally`. Guard: 19-android-project.js.
15. **widget/PsyncSnapshot.java, PsyncWidgetPlan.java and countdown/PsyncCountdownPlan.java import NO `android.*`** (`java.*` and `org.json` only): that is what lets app/src/test run them on CI's JVM — put `Context`, colours-as-resources and `RemoteViews` in `PsyncWidgetViews` / `PsyncWidgetStore` instead. Times stay DEVICE-local (agents/decisions.md section 4, CLOSED). `PsyncWidgetPlan` ADDS a card's rows up from sizes copied out of widget_styles.xml and the two layouts (its named constants): change a text size, a tile, a margin or the badge's padding in the XML and change the constant with it, or a plan "fits" a height it no longer fits and the seat badge — the last row — is cut. Guard: 19-android-project.js (no `android.*`; every constant against the XML); the tests themselves run only in `android-build`.
16. **A new snapshot field is OPTIONAL, with a fallback, on BOTH platforms**: an older snapshot is still stored after an update (learnings G2), and `'null'` / `'[]'` / a missing key mean "Nothing booked". Add it to the bridge's `_snapshotEventFor`, read it under a default in `PsyncSnapshot.Entry.from` AND in PsycleShared/PsycleSnapshot.swift, add a JVM test. The store takes the three snapshot keys (`isWidgetKey`), strings of at most 64 KB, and ONE more that is no part of the snapshot: `countdown_enabled`, `'1'` or `'0'` and nothing else (`isStoreKey`, `fitsKey`), which the bridge writes on Android only; never written = OFF (`countdownEnabled`: only `"1"` is on — the countdown FOLLOWS a preference only the page can read, so a plan run before the page has said shows nothing). A fifth key, `countdown_dismissed`, is NATIVE ONLY (`PsyncWidgetStore.countdownDismissed`): it is not in `isStoreKey`, so the plugin — the page — can neither read nor write it.
17. **WidgetPreviewActivity lives under app/src/debug/ ONLY**, with its own manifest: exported so `adb` can start it, therefore never in a release — and behind `android:permission="android.permission.DUMP"` (named, not requested: the adb shell holds it, no installed app can), because the debug APK is also what gets sideloaded onto a signed-in phone. It reads nothing stored and sets no click; a widget it cannot draw is logged under the tag `PsyncWidgetPreview`, which `android-smoke` greps for — rename both or neither. Beside it, the same way (debug only, exported, behind DUMP): `CountdownProofReceiver`, which DOES write — ONE fixed sample class into the store, `minutes` ahead (or `started` / `clear` / `enabled`; the sender picks a number, never a word) — then runs the real `plan()`; a receiver, not an activity, because `am start -S` force-stops the app and a force-stop removes its notifications by itself. Every extra is a STRING (`--es`, `getStringExtra`): a typed one (`--ei`, `--ez`) reads as null, and the DEFAULT sample would be judged as the one asked for. It answers `am broadcast` with what it did (kept in countdown-broadcasts.txt) and logs a failure to seed at ERROR under `PsyncCountdownProof`, which `android-smoke` greps for — rename both or neither; it reads no action and has no intent filter. Guard: 19-android-project.js holds the component, the extras and the tag to ci.yml's script.
18. **The class countdown is ONE silent, ongoing notification, and one that outstays its class is worse than none.** countdown/: `PsyncCountdownPlan` (PURE: the FIRST class to come, shown from `LEAD_MILLIS` = the iPhone's 90 minutes until its start; `nextWake`), `PsyncCountdownNotifier` (tag `psync-countdown` + id 7090 — the tag keeps it out of reach of the local-notifications plugin's tag-less ids; channel `class-countdown`, IMPORTANCE_LOW, created natively — NEVER rename it; PRIVATE, with a public version that names no class, place or seat), `PsyncCountdownReceiver` (`plan(Context)`: static, synchronized, idempotent, never throws; takes NOTHING from an intent; ONE inexact `AlarmManager.setWindow(RTC, at, ten minutes, …)` — never the bare `set(…)`, whose window is the system's: up to an hour late from Android 12, and on API 22–25, where that alarm alone takes the notification down, an hour PAST the class: G16), `PsyncCountdownDismissReceiver` (the notification's DELETE intent: from Android 14 a member can swipe it away, and a swipe is an answer for THAT class at THAT start — it records `PsyncCountdownPlan.keyFor(id, start)` natively, the plan then shows nothing for it and keeps its wake, and the receiver forgets it once the plan is about anything else; the system's timeout sends the same intent, harmlessly). It ends by `setTimeoutAfter` from API 26 — the system removes it with the app dead; below 26 it is posted only once its alarm is armed — and WHETHER to post is the pure `PsyncCountdownPlan.mayPost(alarmArmed, systemEndsIt, canPost, now)`, so the JVM tests run the rule. NO foreground service, NO exact alarm, NO new permission (`POST_NOTIFICATIONS` and `RECEIVE_BOOT_COMPLETED` are @capacitor/local-notifications' own, merged in: re-check its manifest after a plugin bump), and it NEVER asks for the notification permission — `canPost` only looks. Every API above 22 sits behind `Build.VERSION.SDK_INT` in the SAME method. The class reminder (`class-reminders`, the bridge's) is another notification and stays as it is. Guard: PsyncCountdownPlanTest (JVM — and ci.yml PROVES it ran: a class named …Countdown…Test, so keep that in the name); 19-android-project.js (what can be read: the channel and its importance, the builder calls, the `SDK_INT` tests, the two receivers and the four filter actions, the delete intent, the ten-minute alarm window and no bare `set(…)`, the permissions, the ONE tap builder); 21-android-countdown.js (the bridge's switch against `isStoreKey` / `fitsKey`); `android-smoke` posts a real one and reads it back. Until that job has been read it is "read, not built"; after it, "posted on an emulator, not seen on a phone".
19. **The tip jar sells three things and touches nothing else.** `PsycleTipJarPlugin` (Play Billing 8 — the ONE runtime dependency this module adds; do not add another without the owner) + the PURE `tips/PsyncTips`: an id is checked against `PsyncTips.IDS` before anything, a purchase is consumed only when EVERY product in it is a tip, and the purchase token goes to `consumeAsync` and NOWHERE else — never to the page, a log or storage. The ids are the iPhone's and js/tabs.js's: change one, change all three and both stores → 24-tip-jar.js, `PsyncTipsTest`.

## After you edit
From the repository root:
```bash
npm run ci              # 19-android-project.js reads this folder; nothing here needs `cd ios-app && npm run build`
npm run agents:index    # only if a suite or the bridge changed with it (Java and XML are not indexed)
```
Then push the branch and read `android-build` — the JVM tests run first and block — and the advisory `android-smoke` artifact: launch.png, after-back.png, logcat.txt, the nine widget-*.png, logcat-widget.txt, then the countdown's — countdown-broadcasts.txt (what the hook answered), countdown-posted.txt, countdown-shade.png, countdown-after-start.txt, countdown-alarms.txt, logcat-countdown.txt. With a toolchain: `cd ios-app && npm ci && npm run android:test && npm run android:debug`.
